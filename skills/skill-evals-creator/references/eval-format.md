# 用例格式与文件约定

采用参考指南的核心字段。以下示例为本技能原创的合成任务：

```json
{
  "skill_name": "meeting-actions",
  "evals": [
    {
      "id": 1,
      "prompt": "帮我列个行动项表：林禾说她周五整理好访谈结论，演示页也要更新，负责人和时间都没定。",
      "expected_output": "Markdown 表格包含访谈结论和演示页更新两项。访谈结论的负责人为林禾，截止时间为周五；演示页的负责人、截止时间均为待定。",
      "files": []
    }
  ]
}
```

`skill_name` 是被测技能名，不固定写成 `skill-evals-creator`。`id` 使用唯一正整数，增补时保留已有编号。`prompt` 与 `expected_output` 为非空字符串；`files` 是文件路径数组，无文件时写空数组。指南将输入文件视为可选，因此检查器也接受省略 `files`。这些类型、ID 和路径检查是本技能的本地约定，不是所有执行器的通用协议。

首轮后可为用例新增 `assertions`，值为非空字符串数组，一条表达一个可核对条件。不要把内部评分答案写进发送给被测模型的提示词或输入材料。人工审美反馈写在说明文件，避免强行布尔化。

## 路径与样本

- 本技能新建的文件路径统一相对于**目标技能根目录**，例如 `evals/files/meeting.txt`，不是相对于 `evals.json` 所在目录。请求中提到的输入路径与 `files` 保持一致；如果运行器重新映射路径，在交接说明中标出映射。
- 正常输入应实际存在；有意损坏的文件也要真的创建，例如包含不合法 JSON 的 `.json` 文件。不要只命名一个坏文件却没准备内容。
- 故意测试文件缺失时，让 prompt 指向缺失文件，`files` 只列实际提供的文件，并在 notes 中注明这是预期缺输入的用例。
- 新建样本不引用绝对私人路径，不使用跳出目标根目录的路径。复用已有外部材料时复制到约定目录前检查范围和授权；本地链接指向目录外的内容也视为外部材料。
- 不把账号凭据、生产数据或必须访问外部系统的操作混进合成样本。对于发布类技能，用例预期可描述待审批产物或模拟交互，执行权限仍由用户决定。

## 增补现有用例

先解析原 JSON，保留有效用例、ID、自定义字段和文件内容。新增 ID 取未使用的正整数。修订既有 expected_output 时记录原因，不通过放宽标准把失败“修成”通过。遇到不同字段契约时先适配用户执行器，不静默转换丢字段；自带检查器可以跳过不认识的扩展字段，但这不等于验证了它们。

## 检查范围

`scripts/validate_evals.py` 是只读结构检查器，退出码 0 表示结构和已列文件满足上述约定，1 表示检查失败，2 表示命令行用法错误。不检查业务正确性、内容覆盖、prompt 内所有路径或模型表现，也不运行任何被测技能。
