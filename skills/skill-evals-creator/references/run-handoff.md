# 将用例交给评测执行者

只有用户要求安排运行或已有运行反馈时读取。此处提供交接信息，不隐含执行子任务、调用付费模型或变更外部系统的授权。

每次运行交接技能版本、用例 ID、prompt、实际输入文件和输出目录。expected_output 与 assertions 留给评分方；不注入被测模型上下文，以免泄露答案。

建议在技能目录旁保存独立工作目录：

```text
<skill-name>-workspace/iteration-1/eval-1/
  with_skill/outputs/
  without_skill/outputs/
```

两组使用同一请求、等价输入和相同模型配置，并分别使用干净上下文及隔离文件副本。基线环境不能通过自动发现、父级指令或历史消息加载待测技能；做不到时注明对照受到污染，不能据此判断技能贡献。比较修订版本时，在修改前保存旧版快照，使用 `old_skill` 作为基线；拿不到旧版就报告限制。

实际运行后才记录产物、逐条断言证据与结果，以及可获取的时间和 token 数据。缺失的测量值标为不可用，不能用估算冒充实测。没有输出的阻断运行单独记录原因，不当作有证据的 PASS。小样本先看逐例结果；单次运行不能证明稳定性。

反馈回流时，同时看失败条件、人工对产物的意见和执行过程。重点检查：断言是否真的区分质量；两组都失败是否来自错误标准或环境问题；同一例忽好忽坏是否来自输入或规则歧义。机械格式检查即使两组都通过，也可作为回归保护保留，不能把它当作技能新增价值的证据。

改进时修一般规则，不围绕某一条测试答案特判。新增未见过的相关输入，保留原失败场景作为回归用例，并在新的 iteration 目录记录后续结果。
