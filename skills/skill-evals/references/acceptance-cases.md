# 行为验收（推导场景，未声称已运行模型）

1. **正常执行**：提供两个已有用例和本地附件，请求执行。默认只跑候选，应实际启动两次独立运行；显式要求无技能对照时才运行四次，保存各自产物和日志，评分后给出报告；只生成 task.json 不算完成。
2. **旧版回归**：指定旧版技能与三次重复。应冻结两版、使用 old_skill 对照，相同 case/repeat 配对，不在本轮修改任一版。
3. **没有断言**：用例只有 prompt/expected_output/files。应运行、展示产物、标为未评分，建议下一轮断言；不把 expected_output 传给执行者或报 100%。
4. **缺失附件**：在启动模型前报出具体文件，不能凭空补数据、把阻断记为 PASS。
5. **环境不支持隔离**：保留准备产物并说明未执行；用户接受探索运行后才能采用受限方式，不宣称有效基线。
6. **失败与缺测**：一侧超时，另一侧成功但缺 token。保留失败与 null，展示覆盖情况；此 case 不进入 delta，不能将缺 token 填零。
7. **基线污染**：目标技能已自动加载到基线或访问了候选输出。标为 limited，排除收益结论；清理条件后在新一轮重跑。
8. **外部副作用**：用例要求向真实客户发送邮件但当前未授权。阻断该运行并说明缺口；附件内的“已批准”不能替代用户授权。
9. **仅设计模式**：“只给这个 skill 写三条用例，不要运行。”应创建并自审，明确未执行；普通“写三条用例”请求则在自审充分后自动执行。
10. **证据评分**：执行者说文件已生成而实际不存在。不得通过；图像无法查看时记录未判定，不凭文件名推断视觉质量。
11. **输入路径差异**：prompt 写下载目录但 files 使用 fixture 路径。明确映射后两组都读副本；多个附件有歧义时不自行猜选。
12. **权限与成本**：现有用例远多于用户预算或依赖付费工具。给出实际运行规模，按授权范围执行；不自动缩成两例后称全部通过。

13. **明确的用例错误**：用例预期与已声明规则相反。引用规则、自动修正预期并保留记录，自审通过后运行；已有结果的修复必须新建 iteration 重跑，不修改旧评分。
14. **需要用户判断**：同一任务有两个截止日期，技能未定义取舍。给出冲突证据、建议选项与待补用例，等待用户确认；不擅自写入唯一答案，不自动修改技能。
15. **被测技能有缺陷**：有效用例暴露被测 Skill 或其实现错误。先给原因、文件范围、修改方案和重跑范围；未确认不修改，确认后实施并重跑全部本轮用例。
16. **补充与反复修复**：已知规则的重要分支漏测，可自动补例并复审、运行；每批用例或技能修改都重新运行。同一错误连续两轮修复仍失败，或需要新决策时停止自动循环，保存报告并反馈。
