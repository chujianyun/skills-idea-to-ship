# 新手引导与示例

## 从“不知道测什么”推进

用户：“我有个整理会议纪要的技能，但不知道怎么写测试。”

可以回应：“先测两件常见的事：能否从讨论里提取行动项，以及遇到没定负责人的事项会不会乱补。比如用一段含有‘周五交初稿’但没说谁负责的记录，看看它是否保留截止时间、把负责人标成待定。你的技能平时输出什么格式？”

这里的示例是待核对的建议，不是已经知道用户要求“负责人待定”。读到技能规则或得到回答后再固定预期。如果上下文已经明确输出格式，直接生成草案，不再提问。

## 按缺口选问题

| 缺口 | 可用的问题 | 用户说“不知道”时 |
|---|---|---|
| 用途未知 | “你最想让它帮你完成哪件事？举一句你会发的请求就行。” | 举两种任务形态帮用户表达，不擅自选业务 |
| 成功标准太虚 | “你拿到结果后，第一眼会检查什么？” | 提出一个有输入依据的可观察结果供修正 |
| 没有真实材料 | “有没有一份可用的小样本？” | 能替代时创建合成样本；不能替代时记为待提供 |
| 不知道边界 | “上次它做错过什么，或者你最担心它乱补什么？” | 从实际规则选一个最相关的缺输入或冲突场景 |
| 规则冲突 | “这里写保留缺邮箱的客户，你又希望删除，是要测哪条规则？” | 暂缓该例的正确答案，先完成其他用例 |

不把本表变成逐项问卷。用户已经提供一个真实失败案例时，先围绕它产生价值，再考虑扩大覆盖。

## 完整推导示例：会议行动项

下面是合成示例，不是用户事实，也不是必须套用的业务规范。

假定技能已声明：把会议文本转换成 Markdown 行动项表，列出事项、负责人和截止时间；原文未指定的字段填“待定”，不执行任务、不通知参与者。

样本 `evals/files/meeting.txt`：

```text
林禾：我负责整理访谈结论，周五交第一版。
赵川：演示页还需要更新，负责人下次再定，时间也没确定。
```

可以构造：

1. **普通请求**：“把 evals/files/meeting.txt 整理成行动项表。”预期：两项；第一项负责人林禾、截止时间周五；第二项负责人和时间均待定。当前日期不参与推断。
2. **表达变化**：“照这段聊天列下谁要做啥：林禾说她周五交访谈结论，演示页先放着，没定人也没定时间。”预期：依据语义和技能的任务提取规则整理；如果“先放着”是否算行动项未定义，这一例先留待定，不替用户悄悄决定。
3. **边界**：“内容只有‘大家交流了近况，没有后续安排’，帮我整理行动项。”预期：明确未找到行动项，不凭空分配任务；表格为空还是省略，可接受技能允许的形式。

获得首轮输出后，第一例可补两条独立断言：“访谈结论的负责人为林禾”“演示页的截止时间标为待定”。“写得像专业秘书”应改成人工反馈问题，例如“这张表是否能让参会者直接确认自己的下一步？”

## 从模糊反馈转成用例

用户反馈“经常瞎编”：先看真实输入和输出，定位到底补造了人名、日期还是事项。保留导致误判的最小上下文，写一个能复现问题的新请求。预期明确“不添加未在材料中出现的负责人”，而不是笼统的“不得幻觉”。涉及私密记录时先用结构相同的合成内容替换；替换后说明这是复现设计，尚未证实仍能触发原失败。
