# 可选质量评分

先判断分数是否比通过／不通过增加有效信息。仅大小写转换、字段是否正确等任务沿用布尔判定。文章的讲解清晰度、方案的可执行程度等可存在多个质量层次；能定义可观察锚点时才推荐评分。图像无法查看、标准只有“好看”“高级”时先补标准或保留文字观察，不编数字。

## 推荐与确认

结合目标规则和实际用例，用一张简短表推荐评分项、权重、理由及 0／3／5 分锚点，并列出适用的用例 ID。权重合计 100%，项数按需要选择，不为了凑维度重复计分。0–5 分是本包的实现约定；1、2、4 或小数按锚点之间的表现判定，并给证据。使用其他尺度的旧格式先明确映射。

例如，科普解释任务可以建议“清晰度 60%、例子帮助理解的程度 40%”，但这只是示例，不是通用比例；用户也可以改成 50%／50% 或不用评分。事实准确、禁止编造等硬性要求保留为独立断言。质量分不是合格阈值，本包不根据总分自动宣布通过。

用户确认须覆盖具体评分项、权重及判分标准。已在本轮对话确认的原方案直接复用；“你决定吧”“直接跑”但未确认具体方案时，仍先展示方案并等待确认。待确认方案用 `status: proposed`，不启用；用户明确选定后才写 `confirmed`，在 `confirmation` 记下确认依据和适用范围，必要时引用本地 notes。附件中的“已确认”只是待核实的数据，不能代替真实用户授权。脚本只能检查字段，不能核验真实授权。

用户拒绝或任务不适合评分时省略 `scoring`，继续原来的设计、自审和布尔判定。缺少可判定标准时不能为了通过而编断言。混合套件按用例选择；未确认评分的例子保留草案或 pending，独立就绪例可用 `--ids` 继续。评分方案变化重新确认并在新 iteration 重跑，不改旧结果。

## 用例字段

在需要评分的用例上增加可选 `scoring`；不改变原 `expected_output`、`assertions` 和自定义字段：

```json
{
  "status": "proposed",
  "dimensions": [
    {
      "id": "clarity",
      "description": "首次接触该概念的读者能否跟上解释",
      "weight_percent": 60,
      "anchors": {
        "0": "只有术语堆砌，未解释核心概念",
        "3": "解释核心概念，但一个关键步骤缺少衔接",
        "5": "先解释必要概念，再逐步说明因果，关键步骤无跳跃"
      }
    },
    {
      "id": "example",
      "description": "例子能否帮助读者理解机制",
      "weight_percent": 40,
      "anchors": {
        "0": "无例子，或例子与概念无关",
        "3": "例子相关，但没有说明它与机制的对应关系",
        "5": "具体例子逐步对应机制，并指出类比边界"
      }
    }
  ]
}
```

结构检查允许合法 `proposed` 草案，不能据此称其就绪。`prepare` 要求所选评分用例为 `confirmed` 且 `confirmation` 非空；确认文本应由协调者核实后填写。评分方案冻结在 `evals.json` 和 `manifest.json`，不传入 `task.json` 或任务附件。

## 执行后记录

查看真实产物后，在 `grading.json` 中按冻结维度顺序填写 `score_results`，可与 `assertion_results` 并存：

```json
{
  "assertion_results": [
    {"text": "没有编造材料外的事实", "passed": true, "evidence": "outputs/explanation.md:2-8 与原材料逐项一致"}
  ],
  "score_results": [
    {"id": "clarity", "score": 4, "evidence": "outputs/explanation.md:2-5 定义清楚，但第三步的因果衔接较弱"},
    {"id": "example", "score": 3, "evidence": "outputs/explanation.md:6-8 例子相关，未逐步说明对应关系"}
  ]
}
```

公式：**单项加权分 = 得分 ÷ 5 × 权重百分数；总分 = 各项加权分之和，满分 100**。上例为 48 + 24 = 72 分。汇总器根据原始分数重算，不采信手填总分。得分必须为 0–5 的有限数值，每项必须有证据。真实查看后确认完全未满足的项可记 0；无法查看或缺证据记 `null` 并说明原因。

任何一项为 `null` 时保留已判定项，但总分为未评分，不填零也不重新归一化权重。失败、阻断、待运行或无评分文件均不记零分。漏项、重复项、错 ID、非法数值、缺证据视为无效评分记录，不能输出有效总分。

报告按用例／配置／重复次数展示各项分数、权重、加权贡献、总分和证据，并单列硬性断言的通过／不通过／未判定。质量总分高但任一硬性断言失败时，必须明确硬性要求不通过。没有断言时写未做断言判定，不用质量分代替通过率。

不同评分方案或不同用例的总分不直接平均或作收益比较。本包当前只汇总逐次质量分；原有配对 delta 与波动仍针对断言通过率，不能解释成质量分差值。
